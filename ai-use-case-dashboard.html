Core principles

Same questions, same scoring, every time — six themes that decide what we build and how we win.

Hypothesis first

Start with what we believe and what would disprove it. Every use case states up front what would tell us to stop.

02

Evidence before scale

Pilots exist to answer a question, not to prove we were right. Stop is a successful discovery — it cost four weeks, not two quarters.

03

Value and feasibility together

Neither one alone gets a use case funded.

04

Finished, not launched

Done means a business routine, a named owner, and measured value — not shipped.

Connected data

06

Speed is a governance outcome

Risk, Legal, and MRM engage early and by tier — controls are why we can move.

02

What actually holds it together

Take any one of these away and the process becomes a list of meetings.

One front door

Every idea arrives through the same fifteen-minute form and becomes a Jira issue with an ID. There is no side channel, so the portfolio on the dashboard is the whole portfolio rather than the part that happened to get written down.

A decision right at every stage

Each stage names the forum that can move it and the record that proves it moved. A use case cannot sit between stages, because sitting is itself visible: the dashboard counts days against the stage target and the update.

A capacity line, not a wish list

Ranking by WSJF only matters if something stops at the line. Committed delivery work consumes the points first, and what is left decides how far down the ranked backlog we get. Below the line means waiting for room, not rejected.

Exits are outcomes, not failures

Work leaves the spine at every stage, and each exit is recorded with a reason: reused, partnered, reshaped, parked, deferred, declined. Declining early is the cheapest thing the process does, and declines stay in the portfolio as data.

The loop at the left is what makes it a system rather than a pipeline: measured actuals go back into how the next estimate is sized.

                AI first

                The AI Operating System

                Written piece

                How I run my own work with AI as infrastructure rather than a search box. An argument, not sample data.

                The premise

                Most people use AI as a better search box. Ask a question, get an answer, close the tab, lose everything. The knowledge evaporates the moment the session ends.

                This pattern inverts that. The assistant doesn’t have a memory, it lives inside one. An instructions file is read at the start of every session, before any other work, so every session boots into full context instead of starting from zero. The org chart, the active programs, the conventions, the open decisions are all loaded before the first question is asked.

                That’s the shift. AI-first isn’t “we use Copilot a lot.” It’s “the system of record is machine-readable, and the assistant is a first-class operator inside it.”

                01

                Information

                Make the organization’s knowledge addressable. Nothing else works until this is true. The foundation is a deliberate memory topology.

                A boot sequence

                Consult the folders for context on any question about work, programs, or deliverables without waiting to be told. The assistant orients itself.

                A privacy boundary that’s enforced, not hoped for

                Personal material goes to private memory. Shared strategy, reference docs, and source-system data go to team memory. When the classification is unclear, ask. Individual 1:1 notes never leak into team space.

                A navigation contract

                Read a folder’s README first: purpose, file listings, subfolder descriptions. At session start, read the top-level README and each immediate subfolder README. Two levels only. Go deeper only when a task requires it. Bounded, predictable, cheap.

                Conventions that keep it parseable

                Markdown first, structured data only when something needs parsing. Link, don’t copy, so facts are referenced rather than duplicated. Minimize new files and add sections to existing ones. This is what stops a knowledge base from rotting into a folder graveyard.

                People as data

                When a name comes up and the profile isn’t known, check the personnel folder. If it’s still missing, ask enough questions to build the profile, then offer to add it. The system gets smarter about the organization every time it meets someone new.

                Information stops being something you remember and becomes something you query.

                02

                Action

                Encode the judgment, not just the facts. This is the layer almost nobody builds, and it’s the one that matters. Facts alone produce a chatbot. Facts plus protocol produce an operator. The point is to write down how decisions actually get made, so the assistant can execute them the way the owner would.

                The Inventory Protocol

                Notes get captured, never applied silently. No existing content changes without review. It runs append-only into an audit log, stamps every entry with date, person, and channel, and sorts everything into What’s New, What We Need to Know, and Decisions Needed. Second-hand information is flagged as [Unconfirmed] until a human confirms it. Conflicts don’t get resolved by guesswork: where an incoming item disagrees with the inventory, the inventory stands and the new value is logged as an open item rather than applied.

                The Review Gate

                A standing quality check that encodes one reviewer’s editorial standard as a repeatable pre-flight. Before anything goes to the reviewer, run it against the checklist. MECE is the primary standard. Report what passes, what fails, and the specific fix. Never silently rewrite the work.

                The Support Guide

                A routing brain with a learning loop. Check the answer log first, because if the question has been answered before, the answer already exists. Answer it only if it traces to something real, and never guess. If it can’t be answered, route it: canonical resource first, then a named person, and say plainly that this is a routing, not an answer. Every new answer gets logged, so the guide gets faster the more it’s used.

                Human-in-the-loop by design

                Draft email and chat messages, don’t send or post without an explicit go-ahead. Don’t overwrite files, create new ones or ask first. If a note would change existing content, stop, show a before and after, and wait. Speed on retrieval and drafting, a hard gate on anything that leaves the building or destroys history. That’s the trade that makes the whole thing safe enough to run fast.

                The assistant doesn’t just tell you things, it does the work, to a defined standard, inside stated guardrails.

                03

                Automation

                Collapse recurring work to a phrase. Once the judgment is written down, the recurring parts stop needing a human at all.

                Reserved commands

                A commands README holds the inventory of reserved phrases that trigger standardized workflows. It’s read at session start, and when a command or a synonym appears, the documented steps are followed exactly. “Add note to discussion topic” is a multi-step file operation compressed into five plain-English words. There’s no syntax to learn.

                The accomplishments flywheel

                Whenever something of substance is completed — a deliverable, a decision, a meeting outcome, a message sent, a file produced — an entry is appended under the current week. The weekly report then writes itself: read the log, then sweep email, chat, and calendar for work that happened outside a session, sorted into Delivered, Moved Forward, Decisions and Escalations, Stakeholder Engagement, and Blockers and Risks. The goal, stated plainly, is a complete weekly account of the work with near-zero manual effort. The reporting burden collapses because the logging already happened as a side effect of doing the work.

                Programs built for humans

                Utilities live in a dedicated programs folder. No admin rights required, relative paths only, and every program ships a setup guide written for non-technical users. Automation a team can actually adopt, not just admire.

                Integrity under change

                Moves require reference updates: READMEs in the moved item, its parent, and its subfolders, plus a search across all files for links to the old location. Log the relocation and the date. The system maintains itself as it grows.

                Work that used to cost an hour a week costs a sentence.

                04

                Why this is genuinely AI-first

                Each has to hold for the pattern to be more than a filing system.

                01

                Memory is infrastructure, not a feature

                Chat history is disposable. A structured file system with READMEs, conventions, and provenance is durable, auditable, and portable across tools and models.

                02

                Every answer improves the next one

                Answer log, feedback log, audit log, accomplishments log, all append-only, never edited or deleted. The system accumulates rather than resets. That’s compounding, and compounding is the whole game.

                03

                Truth has an address

                Every claim carries a source, a date, and a person. Nothing is fabricated, and the assistant reports only what it actually found. Nothing is deleted either, because a superseded value is preserved as a prior-value line so history stays recoverable. In a regulated environment, that isn’t a nice-to-have, it’s the license to operate this way at all.

                04

                The human stays the decision-maker

                The assistant reads, drafts, routes, checks, logs, and proposes. A person approves. That division is written into the operating rules, not left to good intentions.
